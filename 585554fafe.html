结论先行：不要每天开 8 个网站。真正的更新源头只有一个——GitHub。

一、先讲一个关键事实，能省你大量时间

这些"Skill 平台"，本质都是 GitHub 的爬虫

SkillsMP 官网自己写得很直白：它只是收录 GitHub 上公开的 SKILL.md 文件，"不认证质量或安全性"。skills.sh 也是索引 GitHub 仓库后给你一条 npx skills add 命令。

所以你每天刷 8 个聚合站，看到的其实是同一批 GitHub 仓库的二次加工。

真正会"更新"的地方只有一个：GitHub 仓库的 commit/push。

"聚合站用来发现，GitHub 用来追踪更新。
每天开 8 个网站是体力活，订阅 1 个源头才是机制。"

⚠️ 顺带提醒：各家报的收录量根本对不上，别拿它当参考

平台官网今日显示口径
SkillsMP3,601,416收录的 SKILL.md 文件数（一个仓库可能有几十个）
skills.sh1,487,164可安装条目

三、每日追踪方案（我已经跑通了）

方案：一个脚本 + 每天 9 点自动推送

不用你开 8 个网站。脚本每天自动抓这三件事，生成一份日报：

序抓什么为什么是它
17 个必看源有没有动只要看"今天动没动"，没动就跳过，不用细看
2窗口内活跃更新的仓库按 push 时间排序，星标 ≥50 过滤噪声
3其中是新建的新仓往往代表新玩法，最值得关注

脚本位置

D:\个人知识库\02_模板与方法\skill_daily.py

用法

# 最近 24 小时
python skill_daily.py

# 最近 48 小时
python skill_daily.py --hours 48

# 存成文件（脚本会自动建目录）
python skill_daily.py --out "D:/个人知识库/03_输出报告/output/Skill日报/日报.md"

# 有 GitHub token 就传进来，不受限流
python skill_daily.py --token ghp_xxxxx

⚠️ 一个技术坑，已经替你踩过了

GitHub 未登录状态下限制很紧：

  • 普通接口：60 次/小时
  • 搜索接口：10 次/分钟

我第一版脚本发了 3 次搜索请求，直接 403 限流。现在的版本已经压到只发 1 次搜索，三段内容都从同一份结果里切，并且带退避重试。

如果你想更稳：去 GitHub 生成一个 Personal Access Token（不需要任何权限，只读公开仓库），传给脚本即可，配额变成 5000/小时。

四、我的建议：分三层看，别平铺

频率看什么花多久
每天 就看我生成的这份日报（7 个必看源动没动 + 活跃仓库 Top）+ 顺手点一下 skills.sh/trending 3 分钟
每周 翻一次 SkillHub 的 S 级（按工作流看），挑 1-2 个真正用得上的装 10 分钟
需要时 SkillsMP 搜关键词（只搜不装，找到后回 GitHub 看源码） 按需
"三层里，只有第一层需要每天做。
第二层每周一次，第三层用到才开——这样才可持续。"

五、装之前必须过的四道检查

2026 年 1 月的 ClawHavoc 事件是前车之鉴：341 个恶意 Skill 被分发，专门窃取 Cookie 和 SSH 密钥——连官方商店都没挡住。

#查什么怎么看
1有没有往外发数据在 SKILL.md 和脚本里搜 curl wget requests.post fetch(
2有没有读敏感路径搜 ~/.ssh ~/.aws .env os.environ credentials
3有没有执行外部命令搜 subprocess os.system eval( exec( shell=True
4仓库靠不靠谱星标 >50？3 个月内有 commit？Issues 里有没有安全投诉？

这三件事绝对不做：① 从 SkillsMP 搜索结果直接装 ② 只看 SkillHub 的 S 级就装（S 级评的是"写得好不好"，不是"有没有后门"）③ 没读 SKILL.md 就装。
